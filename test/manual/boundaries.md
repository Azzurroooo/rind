# 补充用户边界流程

遵循 [公共准备与报告规则](README.md)。下列每项可独立要求执行；涉及人为故障时只操作隔离测试配置和本次进程。

| ID / 消耗 | 前置与操作流程 | 通过标准与证据 |
| --- | --- | --- |
| B12：最近会话与草稿 / 一轮 | 完成并关闭一个有历史会话；再打开一个新空会话，查看 `/status`、`/context`、`/sessions` 后退出；执行 `rind -c`。 | 恢复有历史的 ID；空草稿未出现在列表或磁盘；保存两个 ID、目录列表与恢复输出。另在无任何历史的独立 home 执行 `-c`，应得到可用新草稿且不立即落盘。 |
| B13：首次失败与取消 / 可能计费 | A：在测试 workspace 配置不可达的本地 endpoint，首次发消息，等失败后退出；恢复正确配置，以该 ID 重开并续聊。B：真实模型执行较长任务时按中断键，等停止后退出并重开续聊。 | 首次输入被保存且失败/取消有明确状态；错误可见、无永久忙碌；取消后无持续新调用；原 ID 和已完成工具结果可恢复，续聊成功。保留失败与取消各自的 meta、请求和终端输出；端点故障与用户取消必须分别判定。 |
| B14：无效输入与持久化隔离 / 无 | 对空草稿尝试 `run --prompt "  "`、不存在 ID、`--session ../escape`；对有历史 ID 用 `--dir` 指向另一个工作区执行 run；另在测试 home 准备缺 messages/tool_calls 的目录和损坏 meta，按 ID 打开。 | 每条有明确失败，无模型请求；不在父目录创建文件、不偷偷重建损坏会话、不改已有历史。保存退出码、错误和文件前后哈希。 |
| B15：首轮前模型选择 / 一轮 | 打开空草稿，通过 `/model` 选择另一已配置模型；查看 `/status`、`/context`；再发送一条只需简短回答的消息，关闭后重开。 | 选择与查询不建会话目录；首个实际请求使用新选择的模型；落盘与重启后选择一致；无重复 system。保存请求 model、选择界面和 meta。未配置第二个模型则 BLOCKED。 |
| B16：fork 历史边界 / 两轮以上 | 空会话尝试 `/fork`；随后完成两轮有不同标记的对话，按 `/fork` 选择器支持的历史边界创建分支，询问分支中应保留的标记。 | 空会话明确拒绝且不落盘；有效分支新 ID 正常使用，原历史不变；分支只包含选择器所说明的范围，不带被排除的后续标记。保存选择边界、两个历史文件及分支实际请求；模型猜中/猜错不能代替检查请求。 |
| B17：运行中输入与终端可用性 / 两轮以上 | 在真实 TTY 发起较长任务；运行中输入尚未提交的中文文本，另一个终端 send 后续任务；观察输出并调整窗口宽度；按正常交互完成/中断，再发送普通消息。 | 输入草稿不被后台输出覆盖、光标不抢占、中文和长输出不破坏布局；外部任务只接收和执行一次，按界面提示的排队/引导语义执行；结束后仍能继续输入。保存操作时序、turn ID、历史和终端截图；管道模拟不能算 TTY 验收通过。 |

新增场景沿用“前置 → 用户操作 → 可观察结果 → 证据 → 消耗/停止条件”，必要时拆成独立文档。已经复现的确定性缺陷应同时补自动回归，人工验收文档继续保留其用户层标准。
