# 让跑不完的命令自己继续

English | [简体中文](background.zh-CN.md)

目标：测试套件、构建、迁移这类一时跑不完的活，不该把会话卡死，也不该跑完就没人管。

## 它自己会转后台

控制台工具（`bash`）默认只等 **10 秒**（`yield_time_ms`，可在自然语言里让模型调整，上限 60 秒）。超时未结束，命令不被杀掉，而是转入后台继续跑，模型拿到的结果里带上 `task_id` 和状态。回合随之结束，输入框立刻可用。

`notify` 决定完成时怎么通知：

| 取值 | 语义 |
| --- | --- |
| `on_exit`（默认） | 任务结束时把结果投回空闲的会话，自动发起续接，不需要反复问 |
| `manual` | 服务、 watch 类长驻进程用这个：不自动续接，需要时显式读输出 |

## 用 Ctrl+B 看进度

**Ctrl+B** 打开后台监视器：

| 键 | 作用 |
| --- | --- |
| ↑ / ↓ | 选择任务 |
| `c` | 取消任务 |
| `r` | 释放当前等待（不杀进程） |
| Esc | 关闭监视器（不影响后台任务） |

关掉只是隐藏，活还在跑。这些控制台任务和团队里的任务不是一回事，后者见[把工作派给一个团队](teams.zh-CN.md)。

## 让模型替你接管

模型可以用 `task_control` 工具继续操作：列出任务、读输出（有界）、有限等待、取消。所以"测试跑完了吗"这种话直接说就行，它会去读而不是盲目重跑。

## 跨回合的目标

有些工作不止"一条命令"，而是持续多轮的目标（跨压缩、跨重启）。用 `/goal`：

```text
/goal                    查看当前目标
/goal <一句话目标>        设定/更新目标
/goal pause | resume     暂停/恢复
/goal clear              清除
```

目标带检查点，回合结束时评估进展，完成需要证据。它和后台命令是两套机制：一个是**进程级**的活，一个是**任务级**的方向。
