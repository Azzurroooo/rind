# 会话流程 S01–S08

先完成 [公共准备](README.md)。每例注明实际 session ID；独立执行某一例时，重新建立其前置状态，不依赖某次旧报告。`<id>` 表示用真实 ID 替换的占位符。

共同标准：操作不污染其他会话；无输入重叠、错误吞掉或退出后遗留本次子进程。成功对话使用真实模型；所有拒绝路径要求不产生模型请求。

## S01：run 不指定 session

**前置 / 消耗：** 工作区就绪，记录现有会话目录列表；一轮模型调用。

**流程：** 执行 `rind run --prompt "只回复 RUN-NEW-OK，不使用工具。"`，记录退出码、输出和新 ID。

**通过：** 退出码 0，回答满足要求；恰好新增一个会话目录；`meta.json` 的 ID 与目录一致；用户输入和回答均写入历史，system 消息不重复。CLI 输出不泄露凭据。

**证据：** 输出、退出码、目录前后差异、messages 和实际请求。

## S02：run 指定已关闭、有历史的 session

**前置 / 消耗：** 先用 run 发送“记住本次代号为 ORBIT-739，仅回复收到”，保存 ID，等待进程退出；准备和续聊各一轮。

**流程：** 执行 `rind run --session <id> --prompt "之前约定的代号是什么？不要读取文件。"`。

**通过：** 正确回答 `ORBIT-739`，本轮请求包含先前历史；追加到原 ID，不另建会话；原始历史没有被覆盖。

**证据：** 两轮输出、原目录历史前后内容、第二轮请求。

## S03：run 指定已关闭的空 session

**前置 / 消耗：** 分别覆盖未落盘草稿和旧版已落盘空会话；草稿分支无消耗，旧版分支一轮。

**流程 A：** 启动 `rind`，记下 ID，不发送对话，输入 `/exit`。确认目录不存在，再执行 `rind run --session <id> --prompt "只回复 EMPTY-OK。"`。

**通过 A：** 非零退出并明确提示 session 不存在；不调用模型，不补建这个目录。

**流程 B：** 在测试 home 中准备一份旧版空会话：单独的新目录、schema 2.0 的 `meta.json`、仅含 system 消息的 `messages.jsonl`、空 `tool_calls.jsonl`。元数据使用本次有效会话的规范化 `workspace_root`、provider/model；更换 ID，计数设为 1/0，不复制 turn_state 或 goal。再以其 ID 执行同一 run 命令。

**通过 B：** 正常完成首轮，沿用该 ID；system 不重复；不能因“无历史”把有效的已落盘会话判为不存在。

**证据：** 两个 ID、夹具来源/内容、退出码、请求数量、目录前后差异。B 未准备时单独记 NOT RUN，不能以 A 代替。

## S04：run 指定仍打开的空新 session

**前置 / 消耗：** 终端 A 启动 `rind`，记 ID，保持空会话；无模型消耗。

**流程：** 终端 B 执行 `rind run --session <id> --prompt "只回复 LIVE-EMPTY-OK。"`；随后回到 A 执行 `/status`。

**通过：** 当前契约下 B 明确报 session 不存在并非零退出，因为该 ID 只有 A 进程内的草稿；无模型请求、无目录；A 仍可交互且 ID 不变。需要给 A 发任务应使用 S05 的 send。

**证据：** 两端输出、退出码、目录不存在。若未来决定支持跨进程接管草稿，先调整产品契约与该标准，不能把当前拒绝默认为成功执行。

## S05：send 指定打开的空新 session

**前置 / 消耗：** 终端 A 打开空会话且目录不存在，记录 ID；一轮。

**流程：** B 执行 `rind send --session <id> "记住代号 SEND-581，只回复已记住。"`；等待 A 完整回答并回到可输入状态。

**通过：** send 确认接收，A 真正完成任务；首次按原 ID 落盘；历史只有一次该用户输入及对应回答，没有第二个会话或重复轮次。send 的接收确认不能代替等待执行完成。

**证据：** 两端输出、首轮持久化、请求数量和 ID。

## S06：send 指定打开的有历史 session

**前置 / 消耗：** 打开 S05 的会话，确保上一轮已结束；一轮。也可关闭后用 `rind --session <id>` 重开以验证恢复。

**流程：** B 执行 `rind send --session <id> "之前记住的代号是什么？不要读取文件。"`；等待 A 完成。

**通过：** 回答 `SEND-581`，模型请求带有原历史；原会话追加一次输入，不改变 ID、不重复启动任务。

**证据：** 输出、模型请求、messages 增量。

## S07：send 指定已关闭的会话

**前置 / 消耗：** 分别准备关闭的空草稿 ID 和关闭的有历史 ID；本例发送操作无消耗，历史夹具准备可能消耗。

**流程：** 对两个 ID 分别执行 `rind send --session <id> "这条输入不应执行。"`。

**通过：** 两次都非零退出并提示会话未运行；不会自动启动 worker；无模型调用；草稿目录仍不存在，历史会话内容不变。

**证据：** 两个退出码、错误信息、请求数、历史文件前后哈希。

## S08：空新 session 直接 /compact

**前置 / 消耗：** 打开全新空会话，目录不存在；无消耗。

**流程：** 输入 `/compact`，等待反馈，再输入 `/status`。

**通过：** 立即提示先发送消息；不请求模型、不创建会话或 compactions 文件；终端保持可用。不能先调用摘要模型再因空会话持久化失败而报错。

**证据：** 提示、目录状态、请求数。需要验收 Web/桌面时，另通过其压缩入口重复上述操作并单独记录；CLI 通过不代表其他入口已人工验收。
