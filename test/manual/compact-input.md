# Compact 期间的交互验收

仅在用户明确要求时执行。使用隔离的工作区和 `RIND_HOME`；真实模型沿用用户同意的配置与预算。假 provider 的自动回归不能记为本页的真实模型通过。

## 手动压缩与输入

前置：已存在足够压缩的历史，终端正常工作；先记录当前会话与请求数。

1. 输入 `/compact`，在摘要仍生成时输入一条 steer（Enter）和一条 queue（Tab）。另跑一轮，使用 `rind send` 提交 steer。
2. 压缩期间取回一条输入再提交，并将一条 queue 提升为 steer。
3. 等待摘要和排队任务完成，再提交一轮新问题。另用没有任何排队输入的 `/compact` 验证不会额外发起普通对话。

通过标准：输入框、光标和队列持续可用；压缩完成事件先于业务 sampling；steer 优先、同类 FIFO，每次 sampling 最多消费一条；queue 等前一任务完成；输入 ID 恰好送达一次。无输入时只有摘要请求。下一轮正常成功，消息和工具结果边界合法。

## 自动压缩

前置：通过正常对话和工具读取增长上下文，观察实际 usage；不得用 `/compact` 代替自动触发。

1. 分别在首次 sampling 前触发自动压缩，以及工具结果返回后触发自动压缩。
2. 摘要生成期间提交 steer 和 queue，让原任务仍有后续工具步骤。
3. 检查压缩后的模型请求和任务完成事件，再重启恢复会话继续对话。

通过标准：持久记录 `reason: auto`；steer 进入下一次业务 sampling（若已有更早的 steer 占用该 sampling，则按 FIFO 等待下一次），queue 不提前；工具调用与结果配对完整。原任务、排队任务和重启后的下一轮均可完成，无 reasoning 格式错误。

## 超时、中断与清理

- 摘要真实耗时超过 120 秒时，CLI 应继续等待且可编辑；若没有发生长等待，此项记 NOT RUN，不人为宣称通过。自动回归用虚拟时钟覆盖该边界。
- 摘要生成期间 Ctrl+C：后台请求取消、队列清空、不提交未完成的摘要；之后普通消息能运行。完成后立即中断不会删除已经提交的摘要。
- 空会话拒绝 `/compact`，不调用模型、不创建持久会话目录。
- 记录模型、事件顺序、请求中实际输入、压缩来源范围和 token 用量；先在报告中汇总证据，再停止所有测试进程，删除隔离工作区、会话、trace、凭据及输出。验证没有残留，不触碰用户原始设置和会话。
