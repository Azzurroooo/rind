Rind Architecture

Rind has two product surfaces, frontend-cli and desktop, backed by one Runtime Package.

Runtime Package

agent/runtime/
  core/    execution core and turn lifecycle
  server/  JSONL facade, protocol, commands, lifecycle

The server and core run in one process and share the composition root. There is no server-to-runtime RPC.

Protocol

Both surfaces use the same v2 methods: initialize, session/new, session/list, session/switch, session/replay, session/prompt, session/cancel, model/list, and model/set. Product extensions are namespaced under rind/.

Runtime events use method: session/update with sequence, durability, session/turn identifiers, and a nested event.type.

Entrypoints

frontend-cli/bin/rind.js
  -> python main.py app-server --stdio
desktop Electron main process
  -> python main.py app-server --stdio
