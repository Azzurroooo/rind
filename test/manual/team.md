# Team 用户流程 T18–T23

遵循 [执行、预算与清理规则](README.md)。所有 Team 文件和父子会话都在隔离根目录下；模型调用、时间和 token 按父任务与全部子任务合计，不能只统计 main-agent。用真实模型委派，不能以模拟子结果代替。

## T18：创建、入口与身份

**前置 / 消耗：** 空测试工作区；管理命令不应调用模型。

**流程：** 启动 rind，执行 `/team create acceptance-team`；记录返回的主 agent 工作区，进入该目录启动 rind，执行 `/team list`。分别从 Team 项目根目录、主 agent 目录、普通目录启动并查看 `/status` 和身份显示；再恢复主 agent 的已持久化会话。

**通过：** Team 结构与主 agent 清晰可达；仅正确的 agent 工作区获得对应 Team 身份，普通目录不会沿用旧徽标或权限；恢复后身份仍正确。项目根目录不是 main-agent 工作区，不能仅因在 Team 树内就注册主 agent 能力。已有会话的工作区绑定不能被静默改写。

**证据：** 创建前后目录、命令输出、各入口工作区与身份、恢复结果。

## T19：成员初始化、蓝图与自然语言添加

**前置 / 消耗：** T18 主 agent；init/blueprint/list 无模型消耗，add 需要真实模型。

**流程：** 执行 `/team init`、`/team list`，再次 init；执行 `/team blueprint`，选择一个尚不存在的蓝图创建。再执行 `/team add 创建一个 agent_id 为 counter 的成员，负责精确统计 shared 中的数据行数`。检查成员后，再尝试创建同 ID 成员和不存在的蓝图。

**通过：** init 可重复执行且不覆盖已有成员；蓝图按当前可用列表创建。add 实际调用 `agent_create`，生成合法成员结构，list 中仅出现一次，职责可读；重名/无效蓝图明确报错，不覆盖已有 prompt、memory 或产物。

**证据：** 工具调用、成员 manifest/prompt、列表及重复操作前后哈希。未生成 counter 时不能继续把后续委派算作通过。

## T20：真正委派、交付与会话归属

**前置 / 消耗：** counter 可用；在 shared/data.txt 写入 `alpha\n\nbeta\ngamma\n`，预期 3 个非空行；父子多次模型调用。

**流程：** 向主 agent 发送：“必须委派 counter 统计 shared/data.txt 的非空行数，将结果发布为 shared/count.txt，然后报告结果、发布路径及子 session ID；不要由你自行代做。”随后关闭并恢复父会话，核对委派历史与成果。

**通过：** 实际 `delegate` 使用 counter 和 execute 模式；子 agent 真正读取数据，count.txt 内容为 3；返回可访问的 shared 发布路径和子 ID。子元数据的 owner、workspace、project、parent_session_id 与任务一致，类型为 delegated_task；父子历史各自归档。重启后记录和文件仍一致，不能只有主模型声称“已委派”。

**证据：** 父 delegate 调用/结果、子请求和工具记录、父子 meta、count.txt、恢复输出。

## T21：inspect 与工作区边界

**前置 / 消耗：** T20 成果存在，在另一个成员私有目录放入无敏感内容的唯一标记；若干父子调用。

**流程：** A：要求主 agent 以 inspect 模式让 counter 检查已有统计结果，不改文件。B：在 counter 自己的交互入口请求通过文件工具读取/修改另一个成员的私有标记，并通过 `shared/..` 尝试越界；再读取合法 shared 文件。

**通过：** A 的实际委派模式为 inspect，仅使用只读工具，无文件变动，不产生可恢复的执行子会话 ID；B 的越界文件工具返回边界错误，shared 正常可读。这里只验证文件工具的工作区约束，不据此宣称 shell 或操作系统已实现安全沙箱。模型拒绝尝试时，行为安全但工具边界子项未覆盖。

**证据：** inspect 参数和工具集合、文件哈希、委派结果、越界错误与合法读取结果。临时 inspect trace 同样纳入清理。

## T22：并发与忙碌恢复

**前置 / 消耗：** 两个成员和两个主 agent 会话，均在本次测试 Team 下；多轮。

**流程：** 让两个成员分别执行有短暂等待的任务，写入不同 shared 文件；同时观察是否各自完成。再从两个父会话对同一成员发起会重叠的长任务，记录系统实际串行/忙碌反馈；第一项结束后重试被拒绝的任务。

**通过：** 不同成员成果、owner 和父子 ID 不串线；同一工作区不并发覆盖文件，忙碌可解释，允许的串行行为也须无重复执行；释放后可重试，不遗留死锁。若两次任务实际未重叠，应记并发分支未覆盖。

**证据：** 调用时间、工作区锁/忙碌响应、父子 ID、独立文件和重试结果。

## T23：失败、中断与主会话恢复

**前置 / 消耗：** 可委派成员；可能产生失败调用费用。

**流程：** 分别要求委派不存在的成员、main-agent 自己；再启动正常成员的长任务，在执行中取消父任务。确认执行终止后，再委派一次短任务。另用测试成员的故障配置触发一次 provider 失败，恢复配置后重试。

**通过：** 无效目标不启动子模型；取消能传递给子任务、释放占用并停止继续调用；子失败反馈给父任务且不伪报成果；修复后主会话仍可成功委派。已完成的工具副作用可保留至取证，但全部属于本次清理范围。

**证据：** 各分支错误、取消事件、终止后的进程/请求、重试结果。没有单独可配置的成员 provider 时，故障分支记 BLOCKED，不改用户全局配置。
